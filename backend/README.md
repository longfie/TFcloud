## 后端特性

### 高性能服务架构

* 基于 **PHP 8.4、Webman 2.2 和 Workerman** 构建，采用常驻内存的多进程运行模式。
* HTTP 服务默认监听 `8787` 端口，支持通过环境变量调整 Webman Worker 数量。
* 签到执行、任务调度、邮件发送、失败补偿和系统维护均由独立进程处理，避免耗时任务阻塞 Web API。
* 支持文件变更监控、内存监控和开发环境自动重载。
* 提供 `/health/live` 和 `/health/ready` 健康检查接口，便于 Docker、反向代理和监控系统判断服务状态。

### 模块化插件体系

* 平台功能采用插件化设计，插件代码与核心业务逻辑相互隔离。
* 每个插件可以声明自己的账号字段、配置项、操作动作和执行逻辑。
* 支持查询插件信息、可用动作以及对应平台的账号接入方式。
* 用户可以为同一平台添加多个账号，并独立设置账号状态、执行参数和任务计划。
* 管理员可以统一查看和管理所有用户的平台账号。

当前内置插件包括：

* 百度贴吧；
* 哔哩哔哩；
* 网易云音乐；
* 爱奇艺；
* 小米运动；
* 天翼云盘；
* 哔咔漫画。

### 多种平台账号接入方式

后端提供统一的平台认证流程，根据插件能力支持：

* 扫码登录；
* 账号密码登录；
* 手机短信验证码登录；
* 手动填写 Cookie、Token 或其他平台凭据；
* 登录状态轮询；
* 凭据有效性验证；
* 平台账号资料自动获取；
* 账号凭据更新和重新授权。

临时认证流程具有独立的流程编号、有效期和使用状态，认证完成后会自动失效，避免认证上下文被重复使用。

### 完整的用户认证系统

支持多种用户登录和账号管理方式：

* 用户名或邮箱加密码登录；
* 邮箱验证码登录；
* 邮箱验证码注册；
* QQ 快捷登录；
* QQ 账号绑定；
* 忘记密码和邮箱验证码重置密码；
* 登录后修改密码；
* 修改邮箱前进行邮箱验证；
* 用户资料修改；
* 用户主动退出登录；
* 管理员撤销指定用户的全部会话。

系统支持按后台配置启用登录和注册的人机行为验证，并记录登录 IP、User-Agent、最后登录时间和会话状态。

### 安全会话管理

* 登录成功后创建独立会话，服务端仅保存令牌哈希，不直接保存原始访问令牌。
* 会话包含有效期、最后活动时间、登录 IP 和客户端 User-Agent。
* 支持单会话退出、密码修改后撤销会话以及管理员强制撤销用户全部会话。
* 用户状态或权限发生变化后，可以立即阻止失效账号继续访问受保护接口。
* 普通用户接口和管理员接口分别经过身份认证及管理员权限中间件校验。

### 敏感凭据加密存储

* 平台 Cookie、Token 和其他认证凭据不会以明文形式保存在数据库中。
* 加密数据独立保存密文、随机 nonce、密钥版本和凭据指纹。
* 支持凭据有效期、验证时间和轮换时间记录。
* 平台登录过程中的临时认证上下文同样采用加密方式保存。
* 签到过程中的原始响应可以单独加密存储，并设置自动过期时间。
* 对外接口仅返回经过筛选的安全结果，不直接暴露完整敏感响应。

> 应用密钥和凭据加密密钥一旦投入使用，不应随意更换或删除，否则可能导致已有平台凭据无法解密。

### 签到任务队列

签到操作统一转换为可追踪的任务，由后台 Worker 异步执行。

调度器会逐个账号创建任务，单个账号的旧配置或临时异常不会阻塞其他账号。旧版本仅保存
`schedule_enabled`、没有 `schedule_time` 的账号会沿用数据库中已有的 `next_run_at` 时间；如果没有可恢复的时间，则自动切换为错峰计划。升级旧版 `.env` 时无需补写新增 Worker 开关，
`SIGN_WORKER_ENABLED` 和 `SIGN_SCHEDULER_ENABLED` 缺失时默认启用，显式设置为 `false` 仍会关闭对应进程。

任务系统支持：

* 手动创建任务；
* 定时调度任务；
* 管理员代为触发任务；
* 任务优先级；
* 幂等键，防止同一任务重复创建；
* 最大尝试次数；
* 任务延迟执行；
* 执行锁和 Worker 标识；
* 失败自动重试；
* 用户主动重试；
* 管理员完整重跑；
* 等待中的任务取消；
* 按平台、状态和时间筛选；
* 月度签到日历。

任务状态、执行次数、开始时间、完成时间和最后一次错误都会被持续记录。

### 多层级执行记录

后端将一次签到拆分为三个层级：

1. **任务 Task**：表示用户发起的一次签到请求；
2. **运行 Run**：表示任务的某一次实际执行尝试；
3. **记录 Record**：表示单个贴吧、账号目标或签到子项的执行结果。

每次执行可以记录：

* 插件名称和插件版本；
* Worker 标识；
* 执行次数；
* 总目标数；
* 成功数量；
* 已签到数量；
* 跳过数量；
* 失败数量；
* 错误代码和错误信息；
* 异常类型；
* 执行耗时；
* 奖励信息；
* 业务指标；
* 安全处理后的平台响应；
* 父子记录关系。

用户和管理员都可以查看任务详情、执行批次和逐项结果。

### 贴吧专项补签机制

贴吧任务使用独立的失败补偿 Worker：

* 正常签到 Worker 负责首次执行；
* 补签 Worker 只处理需要后续重试的失败项目；
* 已经成功签到的贴吧不会在当天重复执行；
* 已关闭、已取消关注或不再需要签到的贴吧不会无限重试；
* 管理员完整重跑时会重新获取当前关注的贴吧列表；
* 补签进程数量和启用状态可以独立配置。

### 统一 API 设计

* 所有业务接口统一使用 `/api` 前缀。
* 普通用户接口经过身份认证中间件保护。
* 管理员接口额外经过管理员权限校验。
* API 使用统一的成功和错误响应结构。
* 未匹配路由统一返回标准化的 `ROUTE_NOT_FOUND` 错误。
* 每个请求分配独立 Request ID，便于关联接口响应、日志和审计记录。
* 内置 CORS 中间件，支持配置允许访问的前端域名。
* 关闭 Webman 默认路由，避免未声明的控制器方法被直接访问。

### 网页安装与安装保护

后端提供完整的网页安装 API：

* 检查 PHP 版本和扩展；
* 检查目录权限；
* 测试数据库连接；
* 初始化数据库结构；
* 生成应用密钥；
* 创建管理员账号；
* 写入运行时配置；
* 创建安装锁；
* 返回安装状态。

安装完成后，安装保护中间件会限制再次执行安装流程，防止已有站点被意外覆盖。

Docker 部署时，数据库连接和基础运行参数可以由容器环境自动提供。用户无须预先手动编辑 `.env`，启动服务后直接访问 `/install` 即可完成初始化；安装完成后仍可根据需要修改 `.env.docker` 和后台设置。

### 独立后台进程

系统可以分别启用和配置以下进程：

* `webman`：处理 HTTP API 请求；
* `monitor`：监控代码文件和进程内存；
* `sign-worker`：执行普通签到任务；
* `tieba-retry-worker`：处理贴吧失败补签；
* `sign-scheduler`：创建和调度定时任务；
* `mail-worker`：异步发送邮件；
* `maintenance`：执行系统清理和维护任务。

各进程可以通过环境变量独立启用、禁用或调整数量，便于根据服务器 CPU、内存和任务规模进行部署。
